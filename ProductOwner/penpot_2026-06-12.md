# penpot

## Verdict
Penpot is worth a product owner's time if design collaboration, prototype review, or product discovery handoff is a regular pain. It is not a backlog tool, and pretending it is would be sloppy. Its value is in helping a PO turn user flows, rough concepts, acceptance conversations, and stakeholder feedback into visible product artifacts that design and engineering can inspect.

## What It Is
Penpot is an open source design and prototyping platform for teams building digital products. The repository contains the application code, docs links, deployment paths, plugins, API and integration references, MCP-related work, and release history. It is a tool, not a template library or reading list.

## Why It Is Useful For Product Owners
Penpot helps a PO make product decisions visible. For discovery, it can turn a rough workflow into a clickable prototype that stakeholders can critique. For requirements, it can connect acceptance criteria to screens, states, and interaction paths. For stakeholder alignment, it gives a shared artifact that beats long meetings and vague tickets. For delivery coordination, inspect mode, design tokens, components, variants, and layout behavior help reduce translation loss between product intent, design, and engineering implementation.

## How I Would Actually Use It
1. Build a simple prototype for a new user flow before writing a full backlog epic, then use stakeholder comments to find missing states.
2. Attach Penpot screens to user stories so acceptance criteria include visual states, empty states, errors, and permission behavior.
3. Use design tokens and components to keep roadmap work consistent across multiple squads instead of approving one-off UI guesses.
4. Run design review with engineering using inspect mode so developers can see CSS, SVG, HTML, layout behavior, and asset details.
5. Use shared libraries or templates to speed up low-fidelity discovery work when the team needs a quick concept, not polished UI.
6. Self-host a controlled workspace for regulated or procurement-constrained teams that cannot push product concepts into a closed SaaS tool.

## Limitations / Watch Outs
Penpot will not fix weak product thinking. If the PO cannot define the problem, user flow, or decision needed, a prototype will just make the confusion prettier. It also adds a tool surface that design, engineering, and product must agree to use. Self-hosting gives control but creates operational burden, and the current GitHub issue count is not small. For teams already standardized on Figma with mature design operations, Penpot only wins if open source control, self-hosting, API access, or code-oriented handoff matters.
