# Tarazu

## Verdict
Tarazu is worth a product owner's time if prioritization decisions are currently happening in spreadsheets with weak rationale. It is not a backlog tracker, and it is not open source in any useful reuse sense, but it gives a concrete model for scoring opportunities, showing tradeoffs, and keeping the decision record attached to the work. The value is highest for POs who need to explain why one initiative beat another, not for teams looking for a Jira replacement.

## What It Is
Tarazu is a public source repository for a decision-intelligence web app for product teams. It contains a Next.js and React application, Claude-backed API routes, localStorage guest mode, optional Clerk and Supabase cloud paths, screenshot documentation, tests, and product design records. It is a tool repo, not a template library, and the source is published for inspection rather than permissive reuse.

## Why It Is Useful For Product Owners
Tarazu maps cleanly to backlog refinement and prioritization because it makes reach, impact, confidence, and effort explicit for each candidate feature. It helps stakeholder alignment by giving a visible tradeoff map and a written rationale instead of a silent spreadsheet score. It supports roadmap planning by separating quick wins, strategic bets, fill-ins, and avoid items. It can also improve discovery and experimentation conversations by forcing assumptions and confidence to be named before a sprint plan or roadmap commitment is made.

## How I Would Actually Use It
- Import the next 10 roadmap candidates and score each one with RICE before the next planning meeting.
- Use the effort-versus-impact matrix to separate quick wins from expensive strategic bets.
- Run the AI strategy advisor, then rewrite its recommendation into a human decision note with tradeoffs and caveats.
- Compare stakeholder pet requests against discovery-backed items using the same scoring scale.
- Save screenshots or exports of the ranking before roadmap review so later changes have an audit trail.
- Use the PRD and Validate roadmap docs as examples for how to document product rationale, acceptance criteria, risks, and launch planning.

## Limitations / Watch Outs
The big catch is licensing: the repository is public, but the license says proprietary and all rights reserved, so do not treat it as reusable open-source software. Community proof is weak: 0 stars, 0 forks, and 8 open issues at scan time. It depends on hosted services if you want the full cloud experience: Anthropic, Clerk, Supabase, and Vercel. RICE scores can still produce fake precision if the team does not have real reach, confidence, and effort inputs.
