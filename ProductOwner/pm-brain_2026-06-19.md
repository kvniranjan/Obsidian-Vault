# pm-brain

## Verdict
This is worth a product owner's time if they already use AI tools for product work and need a stronger operating system than scattered prompts. It is not a simple checklist repo. The value is in its structure for context, stakeholders, discovery, work artifacts, research, and growth logs, plus enough agent instructions to make the system reusable. Skip it if you want a lightweight template you can copy in five minutes.

## What It Is
pm-brain is a git-based product management operating system with an AI coaching layer. It is a template library, framework collection, agent instruction set, and working folder model in one repository. The top-level structure separates product context, PM methods, active initiatives, research artifacts, and personal growth. It also includes platform setup guidance for tools such as Claude Code, Cursor, ChatGPT, GitHub Copilot, and similar file-context AI workflows.

## Why It Is Useful For Product Owners
For backlog refinement, it gives a place to keep active initiative context and connect decisions back to evidence. For discovery, it pushes the PO to separate known facts from guesses before jumping into execution. For stakeholder alignment, the stakeholder-avatar and organization-survival folders are bluntly useful because they capture incentives, fears, veto holders, alliances, and prior behavior. For roadmap planning, the repo encourages a current-reality model where product context lives in versioned files rather than drifting across meetings. For delivery coordination, the system can route from messy braindumps into execution artifacts, templates, and documented next steps.

## How I Would Actually Use It
1. Create a `3-Work/` initiative folder before writing a PRD, then keep the problem framing, decisions, tradeoffs, and open questions there.
2. Use `1-Context/1.1-Stakeholder-Avatars/` before a roadmap review to write down what each stakeholder actually wants, not what they politely say.
3. Use the coaching flow before prioritization meetings to force assumptions, risks, and second-order effects into the open.
4. Keep discovery notes and interview synthesis under `4-Research/`, then link them from initiative files instead of pasting the same evidence into every document.
5. Use `2-Methods/` as the source for repeatable product rituals such as framing, prioritization, strategy, and execution templates.
6. Use `5-Growth/` after major launches or misses to record forecasts, what happened, and what should change in future judgment.
7. Adapt the bootstrap instructions into the team's AI tool setup so agents read product context before generating tickets, specs, or plans.

## Limitations / Watch Outs
This repo asks for behavior change. If the PO will not maintain files, the system will rot fast. It is also AI-workflow heavy, so teams that ban file-context AI tools will get less value. The license deserves attention because the LICENSE file says CC BY-NC-SA 4.0, while GitHub API metadata reports NOASSERTION. It is also opinionated about git as the source of truth, which may clash with teams that are locked into Jira, Confluence, Productboard, or Notion.
