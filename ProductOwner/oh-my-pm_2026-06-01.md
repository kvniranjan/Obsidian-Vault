# oh-my-pm

## Verdict
This is worth a product owner's time if they already use Claude Code or are willing to test AI-assisted product workflows. It is not a mature community project, so do not treat it as a standard operating model out of the box. The value is in the reusable workflow prompts and skill structure for PRDs, prioritization, roadmaps, competitive analysis, release planning, and impact review.

## What It Is
`oh-my-pm` is a Claude Code plugin and workflow library for product managers. It contains skills, subagents, command wrappers, templates, docs, and workflow orchestration for product work. It is closer to an AI-agent operating kit than a standalone SaaS tool or static template collection.

The README describes a 5-layer architecture: perception, strategy, design, delivery, and validation. It also includes direct commands such as `quick-prd`, `full-pm-cycle`, and `feature-launch`, plus natural-language skill triggers for tasks like competitive analysis, PRD writing, impact analysis, product positioning, and roadmap planning.

## Why It Is Useful For Product Owners
- Backlog refinement: use `requirement-review` and `prd-gen` to tighten unclear stories before they reach engineering.
- User stories and acceptance criteria: use the PRD and requirement-review workflows to turn vague feature requests into structured requirements.
- Prioritization: use the prioritization skill for RICE or MoSCoW framing when stakeholders are pushing competing asks.
- Discovery: use market intelligence, competitive analysis, and user research skills before committing to roadmap items.
- Stakeholder alignment: use requirement review, project coordination, and release-management workflows to create clearer meeting artifacts.
- Roadmap planning: use roadmap-planning and full-cycle workflows to connect strategy, sequencing, dependencies, and release intent.
- Metrics and experimentation: use impact-analysis, feedback-synthesis, and iteration-planning to close the loop after launch.

## How I Would Actually Use It
1. Run a `quick-prd` style workflow for a vague stakeholder request, then use the result as a first draft for grooming.
2. Use the competitive-analysis skill before prioritizing a parity feature, especially when sales says "competitor X has this."
3. Use roadmap-planning to turn a pile of epics into a staged release narrative with dependencies and sequencing.
4. Use requirement-review before sprint planning to find missing acceptance criteria, hidden dependencies, and unclear user value.
5. Use feature-launch to create a release checklist covering coordination, rollout risk, and stakeholder communication.
6. Use impact-analysis two weeks after launch to compare expected outcomes with observed metrics and feedback.
7. Use feedback-synthesis to turn support tickets, sales notes, and customer comments into backlog themes.

## Limitations / Watch Outs
- Community signal is basically nonexistent right now: 0 stars, 0 forks, and no published releases.
- It is tied to Claude Code workflows, so teams using other AI tools will need to port the ideas manually.
- The repo may overpromise if users expect reliable automation without disciplined inputs, product context, and human review.
- Some generated outputs will still need hard product judgment. A workflow can structure thinking, but it cannot decide strategy for you.
- Setup is not zero-friction. A PO who does not already live near developer tooling may bounce off the Claude Code and plugin assumptions.
