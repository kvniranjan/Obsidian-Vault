# loomio

## Verdict
Loomio is worth a product owner's time if decisions keep getting lost in meetings, chat threads, and half-remembered stakeholder comments. It is not a backlog tool, and treating it like one would be a mistake. Its real value is giving product decisions a visible discussion trail, proposal record, and agreement mechanism before work lands in delivery.

## What It Is
Loomio is an open-source collaborative decision-making application. The repository contains the main product code, README, setup guide, changelog, license, docs, API material, user manual folder, tests, and deployment pointers. It is a working software product, not a prompt pack, template library, or curated reading list.

## Why It Is Useful For Product Owners
Product owners often need to align stakeholders before backlog items become expensive delivery commitments. Loomio can support roadmap tradeoff discussions, feature scope decisions, discovery synthesis, release-go or no-go calls, and prioritization choices that need explicit rationale. It is especially useful when a PO needs to show why a decision was made, who objected, what options were considered, and what agreement actually existed.

It also helps with delivery coordination when teams need asynchronous input from compliance, support, sales, design, engineering, or leadership. Instead of burying product decisions in Slack or meeting notes, a PO can keep a durable thread tied to the decision itself.

## How I Would Actually Use It
1. Create a decision thread for a roadmap tradeoff, such as "ship admin reporting first or improve onboarding conversion first", and require stakeholders to vote with rationale.
2. Use proposals to record scope decisions before backlog refinement, then link the final decision in the Jira or GitHub issue.
3. Run an asynchronous go or no-go decision for a release when support, sales, and engineering cannot attend the same meeting.
4. Capture objections to a feature cut, then use the discussion record to decide whether the cut is acceptable or needs mitigation.
5. Keep product council decisions in Loomio so future roadmap debates start from the actual prior decision, not memory.
6. Use Loomio for discovery synthesis decisions, such as selecting which customer segment or pain point deserves the next experiment.

## Limitations / Watch Outs
This is not a replacement for a backlog, analytics stack, research repository, or roadmap board. Self-hosting adds real operational burden, and the AGPL-3.0 license matters if a company plans to modify and run it as a network service. The product is opinionated around deliberation and consent, so teams that want fast unilateral decisions may find it too heavy. GitHub metadata has no published topics, so discoverability is weaker than it should be.
