# upstep

## Verdict
Upstep is genuinely worth a product owner's time if the team needs a lightweight feedback-to-roadmap loop that can live inside the product. It is not just a reading repo: it gives you SDKs for collecting feedback, voting, moderation, a triage dashboard, public roadmap behavior, and MCP access for coding agents. The catch is that it is young, self-hosting is real work, and the server license needs legal review before company use.

## Why This Repo Was Picked
It won because it maps directly to a painful product owner workflow: collect user feedback, deduplicate and rank it through votes, triage it internally, expose a roadmap externally, and give agents a project-scoped way to act on the feedback. The documentation is unusually specific for a young repo, including SDK setup, environment variables, moderation behavior, REST API shape, plans, billing, and operational notes. It also has a realistic roadmap that calls out reliability, self-hosting, exports, scoped MCP keys, audit logs, roles, and importers.

## What It Is
Upstep is a self-hostable product feedback and roadmap application. The repo is a Turborepo monorepo with a Next.js dashboard and API, PostgreSQL through Prisma, web and mobile SDK packages, REST endpoints, moderation, voting, project dashboards, public feedback feeds, and an integrated MCP endpoint for agent workflows. It is a tool, not a template library or generic prompt collection.

## Why It Is Useful For Product Owners
For backlog refinement, Upstep can turn raw feedback into a ranked queue instead of a Slack pile or spreadsheet. For discovery, it captures user language directly from the product and preserves enough context for follow-up. For prioritization, voting and duplicate handling give the PO a stronger signal than anecdotal requests alone. For stakeholder alignment, a public roadmap and completed-item views make progress visible without exposing private internal tasks. For delivery coordination, MCP access means agents can read, create, update, and comment on project-scoped work from the development environment.

## How I Would Actually Use It
1. Add the feedback widget to the product settings menu and tag submissions by feature area.
2. Review new feedback twice a week, merge duplicates, and promote clear requests into backlog candidates.
3. Use vote count, customer identity, and recurrence to decide which feedback deserves discovery interviews.
4. Publish only committed or under-review items to the public roadmap, keeping engineering tasks private.
5. Use MCP from Codex or another agent to summarize top requests before backlog refinement.
6. Turn completed roadmap items into release note bullets and link them back to the original feedback.
7. Export or manually copy high-value feedback into Jira, Linear, or the team's planning tool until native importers and exports mature.

## Limitations / Watch Outs
This is a young project with 2 stars and 0 forks at scan time, so community proof is thin. Self-hosting requires PostgreSQL, OAuth setup, environment management, migrations, cron or scheduled notification retries, and production backup discipline. The server is AGPL-3.0-only, which may be fine for internal use but needs legal review for modified network-service deployments. The roadmap itself admits missing production niceties such as backup documentation, signed images, SMTP support, stronger roles, audit logs, scoped expiring MCP keys, read-only agent roles, exports, and importers. It is not a replacement for Jira, Linear, Productboard, or a full research repository.
