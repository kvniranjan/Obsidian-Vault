## What It Is
`pm-skills` is a product-management skill library for AI agents. It is not a SaaS app or a generic PM reading list. The repo contains self-contained Markdown skill folders, workflow definitions, command docs, agent-discovery guidance, release assets, generated docs, validation scripts, and a library of sample outputs.

The practical unit is a skill folder under `skills/`, usually with a `SKILL.md`, reference templates, examples, and evaluation fixtures. A PO can install the library into compatible agent environments, clone it for manual use, or copy specific templates into a team workflow.

## Why It Is Useful For Product Owners
- Backlog refinement: use `deliver-user-stories`, `deliver-acceptance-criteria`, and `deliver-edge-cases` to make vague requests testable.
- Requirements: use `deliver-prd`, `define-problem-statement`, and `develop-solution-brief` to turn discovery context into cleaner product handoff.
- Prioritization: use `define-prioritization-framework` when a roadmap debate needs explicit scoring instead of seniority-driven opinions.
- Discovery: use interview synthesis, journey map, market sizing, opportunity tree, JTBD canvas, and competitive-analysis skills to structure evidence before committing scope.
- Stakeholder alignment: use stakeholder summary, meeting brief, agenda, recap, and workflow-stakeholder-alignment materials to pin decisions and open questions.
- Roadmap planning: use product strategy, foundation sprint, design sprint, lean startup, sprint planning, and feature-kickoff workflows to connect objectives to delivery.
- Experimentation: use hypothesis, launch checklist, post-launch learning, release notes, and build-risk review skills to define what should be learned before and after launch.

## How I Would Actually Use It
1. Start with `skills/define-problem-statement/` before writing any PRD, especially when the request is a stakeholder solution disguised as a customer problem.
2. Run `skills/define-hypothesis/` and `skills/define-opportunity-tree/` during discovery to separate evidence from guesses.
3. Use `skills/deliver-prd/` only after the problem, users, success metrics, non-goals, and risks are clear enough to survive review.
4. Use `skills/deliver-user-stories/` and `skills/deliver-acceptance-criteria/` to convert a PRD into backlog slices engineering can estimate.
5. Use `_workflows/feature-kickoff.md` for a multi-step feature start: problem, hypothesis, PRD, stories, and alignment artifacts.
6. Pull examples from `library/skill-output-samples/` before setting team standards, because sample outputs make quality expectations less abstract.
7. Use `commands/workflow-stakeholder-alignment.md` before a contentious roadmap review so objections, owners, and next decisions are written down.

## Limitations / Watch Outs
- This is an AI-agent workflow library, not a product-management system of record. Jira, Linear, Aha, Productboard, Confluence, and analytics tools still need separate integration or manual handoff.
- The catalog is large enough to create choice overload. A PO should start with two or three skills, not try to operationalize all 68 at once.
- The artifacts are only as good as the inputs. A clean PRD generated from weak customer evidence is still weak product work.
- It is heavily skill-file oriented. Teams that ban AI assistants or require all PM artifacts in locked enterprise tools will get limited value.
- Some installation paths are platform-specific. Claude Code has the cleanest plugin path, while other agents may need `npx skills add`, manual cloning, or local discovery setup.
- The repo is moving quickly, so internal process references can drift. Pin a release if a team wants repeatable templates.
